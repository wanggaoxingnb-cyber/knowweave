## A. 产品与真实性

**1. 你们解决了什么问题？为什么值得做？**
收藏家谬误——收藏等于读过，Pocket 死了、微信收藏夹没人打开；加上通用 AI 不懂我，每次从零开始。值得重做的原因是现在的组合拳缺「检验」和「记忆」两个环，而这两环用 LLM 意图路由加本地 Markdown 记忆就便宜地做出来了。

**2. 和 ChatGPT 记忆有什么本质区别？**
ChatGPT 的记忆是黑盒，你不知道它记了什么、也带不走；织识的记忆是本地 Markdown 文件，逐字能看、能改、能拷走。更关键的是我们有「检验」——判题推动掌握度升降，而它只被动记对话，不检验你到底懂没懂。

**3. 和 Claude Projects / Notion AI 有什么区别？**
Claude Projects 是手动维护的项目说明，Notion AI 是替你搭知识库的脚手架，都要用户自己管理；织识是 Agent 自动读写记忆，并主动做三件事：用你熟悉的领域举例、考你、把新旧概念织成图谱。简单说，它们帮你记录，织识帮你学会。

**4. 传统稍后读（Pocket/微信收藏）都做过了，Pocket 还死了，你们凭什么活？**
因为稍后读全死在「只存不消化」，织识的待学习区自带消化机制——每条目的「听个大概」和「开始学」两个按钮，逼着内容往前走；学过的自动归档，周末还提醒你哪些存了没学。Pocket 的教训不是「稍后读没人要」，是「只存不学没人要」。

**5. 「越用越懂你」具体怎么实现？**
每次回答顺带提取信号（身份、熟悉领域、卡点、显式「记住这个」），只记你说出口的，不猜不贴标签；学懂的概念自动进「弹药库」，变成给下一个陌生领域举例的材料。你的画像有个面板叫「它眼中的你」，每条可看可改可删——不是玄学，是透明的规则。

## B. 技术实现

**6. 幻觉怎么控制？🎯**
我们不吹「零幻觉」，但做了三层兜底：回答前检索你学过且来源可溯的概念卡、回答里给出「防混提示」、考你时答错当场指正并回写记忆。踩过真坑：一开始用推理模型生成回答，它的「思考」把输出额度烧光，返回空白——现在所有生成类调用都显式关掉思考，再用 JSON 兜底解析，宁可慢一点也不能空。

**7. 没有向量库怎么做检索和记忆？**
刻意不用向量库：记忆是 Markdown 概念卡加双链，检索用关键词命中加 LLM 意图路由定位概念，个人知识量级下又快又透明。图谱从双链直接生成。等用户量级大了再上向量检索，但那一步是【Roadmap】。

**8. 你们的技术壁垒是什么？**
诚实讲，壁垒不在算法——LLM 各家都有，图谱、OCR 都是现成组件。壁垒是「记忆结构 + 场景闭环」：全 Markdown 的透明记忆 schema、掌握度与弹药库的飞轮、以及存学考编输出一整套闭环的产品设计。这是对手抄不走的三件套，代码只是它的载体。

**9. 一个输入框怎么知道用户想干什么？**
LLM 意图路由，九个意图：讲解、学习、收藏、编织、检验、演绎、导师、创作、闲聊，用户永远不选按钮。路由拿不准就落到最安全的「讲解」，宁可多解释，不错过需求；有链接时优先按「先存着/想学」的语气判定收藏还是学习。

**10. 这个项目是三天做出来的，踩过哪些大坑？🎯**
最大的坑就是第 6 题那个：推理模型的「思考」烧光输出额度导致空响应，演绎功能整整返工过一次；修法是生成类调用显式禁用思考、超时放宽、JSON 截断兜底解析，还把生成过的图解缓存下来秒开。第二个坑是意图路由不稳定，我们把信号提取和概念提取拆成稳定的 JSON 字段，才不串台。

## C. 数据合规与安全

**11. 数据合规怎么讲？（评委必问）**
记忆数据全本地存储、零上传；只有提问那一刻，把本次输入和检索到的相关记忆发给 LLM，记忆库本体不离开你的电脑。key 放 .env 且已 gitignore，不入库、不提交；无账号体系、无云端同步，天然符合「数据合规」。

**12. 以后想做云端 / 多用户怎么办？合规怎么保证？**
那是【Roadmap】，我们会先做本地优先：即使上云也保证记忆文件可导出、可删除，授权走最小化——只把「本次需要的那几页记忆」带给模型，而不是整个知识库。现在先把透明和可控做到位。

**13. 记忆文件是明文，被改了怎么办？被删了怎么办？**
这是设计取舍：明文换来的是「你能看见、能带走」，比黑盒更像你自己的东西。文件被改坏前端会容错降级，概念库有种子备份（04-记忆库样例/），一条命令就能还原到演示状态；真正的数据安全边界我们如实承认需要产品化，不吹。

## D. 商业与竞争

**14. 商业模式是什么？**
个人订阅制，面向持续学习的职场人，价值锚点是「收藏不再吃灰 + 学过的知识不丢」，定价对标知识管理/稍后读工具区间（具体数字待我确认，不编）。后做团队版，把「个人记忆资产」扩展成「团队知识沉淀」，【Roadmap】。

**15. 如果大厂做了（ChatGPT 加学习记忆、Notion 加图谱）怎么办？**
大厂做的永远是「通用智能」，织识守的是「个人知识主权」——记忆是你的本地文件，不是租来的云端记忆。大厂反而帮我们教育市场；我们的先发优势在吃透「持续学习」这一个垂直场景的闭环，这是通用产品懒得做的细活。

**16. 用户为什么付费？留存靠什么？**
因为越用越值：记忆资产在本地持续生长，迁移成本高，换来的是天然留存。弹药库飞轮让「学懂的领域变成下一个陌生领域的垫脚石」能被用户直接感受到——这是订阅制能成立的体验基础。

**17. 市场规模多大？**
我不编数字。定性地说：持续学习的职场人是稳定且庞大的群体，产品经理、运营、文科生、备考和自学者都是；他们今天已经在为 ChatGPT、Notion、稍后读付费，我们切的是其中「想真学会」的那部分预算。

## E. 团队与黑客松视角

**18. 你是产品经理，这代码谁写的？🎯**
用官方点名的 Codex 写的，我就是产品经理兼验收官：需求我定、效果我把关、代码交给 AI 编码工具实现。这正是赛事想证明的事——「不只属于程序员」。撞坑那天（思维烧额度返工）我全程在场和 Agent 一起定位修掉的，不是甩手。

**19. 三天做的 Demo，现场会不会翻车？**
做了三重保险：没有 key 自动进 mock 兜底模式，内置演示答案照样能跑；演示前一条命令重置记忆库到种子状态，图谱、画像都是现成的「用了一周」形态；演绎这类慢功能有缓存，生成过的秒开。最坏情况，我有一台备好所有缓存的本机。

**20. 一句话，你们到底在做什么？**
把「收藏」变成「学完」——织识记得你学过什么、也知道你是谁，用你熟悉的方式，让你真的学会，并且越用越懂你。

## 附录：踩坑故事完整版（口头展开用，不写进 PPT）

**故事一：推理模型的「思考」烧光输出额度（3 个问题里都能用）**
做演绎功能（「画给我看」）时，模型要生成一段完整的 HTML 图解。第一次上线，调用老超时，返回还是空白。定位后发现：推理模型收到长任务先进入「思考」模式，把 max_tokens 额度全烧在思考上，正文一个字没吐。修法分三层：生成类调用显式 `thinking: disabled`、JSON 截断兜底解析（`_extract_json` 从残缺串里捞回合法 JSON）、超时从 60s 放宽到 170s 再收紧到合理的 120s。这个坑证明我们真的在用 AI 的方式做 AI 产品——不是调包完事，是踩过生产环境的坑。

**故事二：意图路由串台（第 10 题展开用）**
早期路由把用户信号和概念提取混在一次输出里，经常把「想要游戏例子」记成「偏好游戏行业」。后来把路由输出拆成 intent/topic/concepts/signals/reason 五个独立 JSON 字段，信号提取稳定了，「它眼中的你」面板才敢上线。现在 profiles/user.md 里的信号每条都有日期、可改可删。
